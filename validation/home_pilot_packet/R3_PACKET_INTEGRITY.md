# R3 packet integrity

`SHA256SUMS.txt` is preserved unchanged as historical R2 portability evidence. It hashes the clean Windows R2 checkout representation and therefore fails against 29 canonical LF Git blobs even though those members are semantically identical after newline normalization.

R3 uses `SHA256SUMS_R3.txt`. Packet text patterns are pinned to LF by `.gitattributes`; binary files receive no text conversion. The R3 manifest is generated by `helpers/build_r3_packet_manifest.py` in deterministic path order and covers every regular packet member except `SHA256SUMS_R3.txt` itself, whose self-reference is impossible.

The R3 manifest's own SHA-256 is recorded in the external operation receipt after the final R3 commit. Verification must pass both in the Builder worktree and in a fresh Linux materialization of that committed tree.
